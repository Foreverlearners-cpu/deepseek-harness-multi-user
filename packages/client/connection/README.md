# @deepseek-ai/dsh-client-connection

English | [中文](README.zh.md)

Wire consumer layer: the client plugin's apply mounts `ctx.connection` (shared api client + current-page loopback state + observable generation-scoped `hostDescription` + single-consumer stream-loop starter); the export face carries the wire contract types, the `AbstractApiClient` abstraction, and the loop's sink/config types. Each successful readiness handshake publishes the exact `host.describe` value before `onConnected`; generation loss and explicit stop clear it, so native-capability consumers never retain a disconnected answer. The browser carrier uses HTTP POST for unary and respond operations and opens one downlink-only WebSocket each for `events.mux` and `events.host`; the in-process carrier satisfies the same two-stream abstraction. The Host half owns the single `/api` route and its Fetch bridge; a registered Typert interceptor claims its Remote endpoints before the API Proxy fallback. Loopback hostname classification stays package-internal: the `/api` Host fence and WebSocket upgrades use it directly, while other client plugins consume the derived `ctx.connection.isLoopback` state. The node half's `/api` route pins the privileged method set (`host.pickDirectory`, `host.openPath`, and the whole configuration plane — `settings.describe`/`openDocument`/`update`/`replace`/`mutate` and `credentials.describe`/`set`/`unset`; reads and native actions included, since describing returns the exposed configuration, opening acts on the Host desktop, and probing an arbitrary reference reports where a credential comes from — and the agent-preset authoring plane, `agentPreset.read`/`copy`/`openDocument`/`remove`, since a composition names the plugins a session runs, so reading one is reconnaissance, and copy/remove/openDocument manage the roster and drive the host desktop (authoring is copy-only, so none of them accepts composition text or a path); `agentPreset.list` and `agentPreset.select` stay out — the roster carries only ids and trust, and choosing a preset grants nothing `session.create`'s own `agentPreset` did not, over a default that already carries bash) to loopback by passing the trust fence with an empty trust list — these operations additionally require their route permission and an authenticated call; the loopback fence is not an identity grant. The platform carriers and ConnectionController loop are package-internal; apply selects and drives them. The downlink boundary is documented in the [WebSocket downlink carrier Agent Note](../../../.agents/notes/implemented/architecture/2026-08-04-websocket-downlink-carrier.md).

## /api browser-trust fence

The fence is a reachability policy, not authentication. It runs first; the secured Host adapter then authenticates the original request and applies route authorization. WebSocket upgrades are rejected before authentication, authorization, or event-source creation when the fence fails.

The node half guards every entry under `/api` before bridging or upgrading (`src/api-request-trust.ts`). Every request — browser-marked or not — must present a `Host` that is a loopback authority or matches a `trustedHosts` entry: exact on `host:port` entries, any port on port-less entries, both sides compared through WHATWG normalization (DNS-rebinding defense). There is deliberately no shortcut for unmarked HTTP requests: over plain HTTP a browser attaches neither `Origin` nor Fetch-Metadata to image and navigation reads, so an unmarked request may still be a rebound browser read with a readable response, and Host is the one header rebinding cannot forge; a browser WebSocket handshake carries `Origin` and passes the same comparison. Non-browser clients pass the same fence via loopback, deployment-derived LAN IP literals, or a declared authority. When markers are present, an attached `Origin` must equal the Host authority, and an explicit `sec-fetch-site: cross-site` marker is refused. A `trustedHosts` entry that is not a bare, canonical `host[:port]` authority — one WHATWG parsing reads back exactly as written — fails the plugin load loudly: parsing would otherwise quietly authorize the hostname inside `harness.internal/path`, or broaden a dangling-colon or zero-padded port to an any-port grant. A real Node request claiming a loopback Host must also have a loopback socket peer (`127/8`, `::1`, or IPv4-mapped loopback), so a remote client cannot bypass local-only or privileged gates with `Host: localhost`. HTTP failures answer plain 403 before any RPC dispatch; upgrade failures reject the handshake before any event stream starts. Non-loopback compositions must trust their serving authorities explicitly: the Web runtime derives LAN IP literals from an all-interfaces server config, while `trustedHosts` in cordis.yml and the CLI's `--trusted-host` flag declare named authorities. `dsh web --host 0.0.0.0` remains intentionally unsupported because the bundled Authentication Provider is local-only. A network deployment must compose a credential-verifying Provider and declare its serving authorities through `trustedHosts`; the fence remains an independent reachability policy and never grants identity. Decision record: [the api browser-trust boundary Agent Note](../../../.agents/notes/implemented/architecture/2026-07-28-api-browser-trust-boundary.md).

## Host authentication and RPC identity

Every accepted RPC request is authenticated by the configured `AuthenticationProvider` while Connection still owns the original `Request`. Generic unary RPC authenticates before reading or schema-parsing its body. When that pre-parse check fails, the Host cannot safely echo the untrusted body rpcId, so it returns the reserved `security-denied` rpcId; clients accept that sentinel only with `unauthenticated` or `permission-denied` and retain strict correlation for every other response. The resulting immutable `AuthenticatedCall` is passed to the Host handler out of band and is never decoded from the JSON envelope or reconstructed from `Host`, `Origin`, loopback state, or client payload. A missing Provider or Provider failure returns `unauthenticated` before dispatch; protected Typert endpoints separately return `permission-denied` when authorization rejects the authenticated call.

This boundary covers registered unary Typert RPCs and the legacy API Proxy surfaces: `/api/respond`, `/api/session.export`, `/api/events.mux`, and `/api/events.host`. Each route has a stable `api:*` permission; Connection authenticates the original request before body parsing or handler dispatch, then passes the call out of band to the secured API Proxy adapter. WebSocket downlinks authenticate and authorize the upgrade request before creating an event source. The loopback/trusted-host fence remains a separate reachability check, so `trustedHosts` is never an identity or account grant. `toFetchHandler(api)` without security options remains available for isomorphic protocol tests; production Host composition must provide its security adapter.

## `/api` WebSocket downlinks

Authentication and route authorization still make the establishment decision, then an `AuthorizationLease` keeps that decision revocable for the stream lifetime. After the final freshness check, Connection opens the lease before handing the upgrade to the downlink. Its signal aborts on call cancellation, credential expiry, policy or permission-catalog invalidation, and Authorization Provider disposal. A decision that becomes stale while its lease is opening rejects the upgrade before event-source creation; an invalidation racing socket acceptance aborts before the source can start.

`/api/events.mux` and `/api/events.host` each accept a WebSocket upgrade and send only the corresponding `ServerRequest` text messages to the browser; the client sends no application data over these sockets. The upgrade passes the browser-trust fence, request authentication, and the route permission gate before the source is opened. The downlink consumes the lease signal by aborting its domain source and closing an open socket with WebSocket policy code 1008 and a generic reason; authorization revocation is not reported as a source `handler failure`. Owned socket/source completion and handled negotiation failures call `release()` exactly once, while revoking one connection leaves the acceptor available so a later attempt can authenticate and authorize again. If either socket ends, the current connection generation fails and rebuilds both streams; readiness still requires both sockets to be open and the `host.describe` HTTP call to succeed. Host teardown terminates both sockets, aborts their sources, releases their leases, and waits for source cleanup before returning. Ordinary network GETs to these paths return 426 with no SSE fallback; the secured in-process SSE path consumes and releases the same lease contract, while an explicitly unsecured `toFetchHandler` remains a protocol-test helper.

## Known Limitations and Deferred Work

- **History resumes an unattached session** — opening history may create the host-side agent and add latency to the first open; there is no persistence-only read path.
- **The `/api` bridge buffers each request body in memory before the Fetch security handler runs** — `maxRequestBodyBytes` (default 160 MiB, sized for the default 100 MiB aggregate image limit after base64 expansion plus envelope headroom) is therefore also the per-request resident bound, including for a credential refusal that passes the outer Host/socket trust fence. A streaming Request or authenticated bridge preflight is needed to close that resource-cost window without shrinking the image limits.
