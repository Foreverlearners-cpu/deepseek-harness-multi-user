# Agent Note: Web 登录展示层

Status: implemented

[English](2026-08-26-web-login-presentation.md) | 中文

## 问题

组装后的 Web 应用会直接进入工作台，但产品需要分别面向普通用户和管理员的入口界面。认证
契约已经独立存在，不过本轮需要先建立并审查展示层，再选择凭据提供方与授权策略。

## 决策

**由一个新的 client 插件持有入口界面。** `ui-auth-login` 向 `shell.overlay` 贡献一个
全屏条目，不修改布局或会话插件。它会等待插槽声明，因此不受 Cordis apply 顺序影响，并会
随自身插件 fiber 一同干净退出。

**普通用户与管理员只是展示模式，不是身份主体。** 分段控件会改变标题、辅助文案、操作按钮
文字与克制的状态颜色。两种模式共用同一套无障碍账号／密码表单和必填项校验。非空值提交后，
浮层只在本地关闭；系统不会调用 Host API，也不会建立角色、令牌、会话或权限。

**只允许持久化非敏感的便利状态。** 用户主动选择后，浏览器可以把去除首尾空格的账号和所选
模式写入 `localStorage`。密码与浮层关闭状态绝不进入存储，因此刷新始终恢复登录边界。
存储被拒绝或旧值格式错误时，界面会退化为空表单。

**未来认证只替换一个边界。** 后续认证插件可以把本地提交替换为 Host 请求。只有 Host 验证
后的响应才能成为身份主体与授权状态的来源；client 的模式选择属于不可信输入，至多用来选择
预期的登录流程。

## 曾考虑的替代方案

**把登录状态放进 AppFrame。** 不采用：认证入口是独立产品界面，这样会让布局归属与身份
问题相互耦合。

**分别创建普通用户和管理员插件。** 不采用：两种模式共享生命周期、字段、校验和响应式布局。
拆成两个包只会重复展示代码，并不会形成安全边界。

**本轮直接连接 JWT。** 不采用：当前要求是不带授权的展示原型。在尚未选定凭据和 Host 会话
边界之前签发令牌，会让界面显得比实际更具有权威性。

## 后果

默认 Web bundle 现在会先打开一个响应式、适配主题的登录界面，并能在普通用户与管理员展示
之间切换。本地提交成功后会显示原有工作台，不改变其组件。测试固定两种模式、表单校验、密码
显隐、账号记忆安全、插槽生命周期和两套语言字典。在 Host 认证器接入之前，部署方必须把它
视为纯展示层，禁止把它当作访问控制边界。
