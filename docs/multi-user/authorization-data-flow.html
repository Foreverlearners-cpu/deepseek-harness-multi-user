版本化缓存

授权变更传播

增加权限可以保守地延迟生效；任何减少权限的 mutation 必须在 MySQL commit 前建立 fail-closed fence。

1. 校验并预留 revisionGrant 必须是 EffectiveDelegate 的子集；事务锁定并复核 evidence。
2. 减权时 pre-fence在持久 head 台账与 Redis primary 安装 deny-until；失败则不 commit。
3. MySQL 事务写 Grant、origin 与 revision，并在同一事务追加 Outbox。
4. 发布 stable headCommit 后替换 fence 与不可变 payload，完成后才返回成功。
5. CDC 异步传播Kafka 消费者更新其他投影，Reconciler 负责补偿修复。

一致性边界

安全优先
MySQL 是权威状态Redis 和搜索投影都不能反向覆盖权威授权。
Grant 可以短暂延迟生效缓存旧数据导致临时拒绝是安全的。
Revoke 不能继续放行pre-fence 或 stable head 无法确认时，相关授权默认拒绝。
CDC 负责修复至少一次消费必须幂等，不能作为即时安全边界。

授权判断规则

基础 CRUD 不是上限；业务插件可以注册 execute、publish、configure 等领域 Action。

功能路线内部取并集

人类 membership 合并所有 active role grant；service account、local profile 与 platform operator 使用各自的有界 grant。

FunctionalUse(human) = R1 ∪ R2 ∪ ...

关系路线内部取并集

资源可以授权给 membership、role、tenant 或 everyone，并合并所有肯定性的领域关系。

RelationshipUse = memberships ∪ roles ∪ tenant ∪ *

路线取交集，Guard 全通过

功能资格不能替代资源关系；任何 required guard 拒绝、缺失、超时或异常都会 fail closed。

EffectiveUse = guards ? FunctionalUse ∩ RelationshipUse : ∅
